Windows 11 / pip / 회사 인증서

pip의 CERTIFICATE_VERIFY_FAILED 오류 해결 정리

회사 네트워크에서 HTTPS 트래픽을 검사하는 환경에서, self-signed certificate in certificate chain 오류가 발생할 때 따라 할 수 있는 절차입니다. 현재 Windows의 현재 사용자 > 신뢰할 수 있는 루트 인증 기관 > 인증서에 LG CNS Co. Ltd v3 루트 인증서가 설치된 상황을 기준으로 정리했습니다.

1. 원인 요약

이 오류는 보통 pip 자체의 문제가 아니라, 회사 보안 장비나 프록시가 HTTPS 통신을 중간에서 검사하면서 회사 내부 인증서로 다시 서명된 인증서 체인을 Python이 신뢰하지 못할 때 발생합니다.

보이는 오류 예시

[SSL: CERTIFICATE_VERIFY_FAILED]

self-signed certificate in certificate chain

현재 전제

LG CNS Co. Ltd v3 루트 인증서가 Windows 현재 사용자 저장소에 설치되어 있음

핵심은 SSL 검증을 꺼 버리는 것이 아니라, 회사 루트 인증서를 pip와 Python이 신뢰하도록 연결하는 것입니다.

2. 회사 루트 인증서를 .cer 파일로 내보내기

Windows 인증서 저장소에 이미 인증서가 있으므로, 먼저 파일로 내보내서 pip에 지정합니다.

  1. Win + R을 누르고 certmgr.msc를 실행합니다.
  2. 현재 사용자 > 신뢰할 수 있는 루트 인증 기관 > 인증서로 이동합니다.
  3. LG CNS Co. Ltd v3 인증서를 찾습니다.
  4. 인증서를 마우스 오른쪽 버튼으로 클릭하고 모든 작업 > 내보내기를 선택합니다.
  5. 아니요, 개인 키를 내보내지 않습니다를 선택합니다.
  6. Base-64로 인코딩된 X.509 (.CER) 형식을 선택합니다.
  7. 저장 경로를 C:\certs\LG-CNS-Root-CA.cer로 지정합니다.

필요하면 먼저 폴더를 만듭니다.

New-Item -ItemType Directory -Path C:\certs -Force
.cer는 Base-64 X.509 형식이면 충분합니다. 개인 키는 필요하지 않습니다.

3. 현재 PowerShell 세션에서 pip에 인증서 지정

내보낸 인증서를 먼저 현재 세션에서 시험 적용합니다.

$env:PIP_CERT = "C:\certs\LG-CNS-Root-CA.cer"
python -m pip install --upgrade pip

환경 변수가 잘 들어갔는지 확인하려면 다음 명령을 실행합니다.

$env:PIP_CERT
이 테스트가 성공하면, 인터넷 자체 문제보다는 회사 인증서 체인 문제였을 가능성이 높습니다.

4. 영구 환경 변수로 등록

매번 PowerShell에서 다시 입력하기 싫다면 사용자 환경 변수로 저장합니다.

[Environment]::SetEnvironmentVariable(
    "PIP_CERT",
    "C:\certs\LG-CNS-Root-CA.cer",
    "User"
)

새 PowerShell 창을 연 뒤 아래로 다시 확인합니다.

$env:PIP_CERT

5. pip 설정 파일에도 인증서 경로 저장

환경 변수 대신 pip 설정으로도 저장할 수 있습니다.

python -m pip config set global.cert "C:\certs\LG-CNS-Root-CA.cer"
python -m pip config list
운영 측면에서는 PIP_CERT 또는 pip config set global.cert 중 하나만 써도 되지만, 환경에 따라 둘 다 맞춰 두면 확인이 쉬울 수 있습니다.

6. pip 업그레이드 테스트

설정이 끝났으면 실제로 연결이 되는지 확인합니다.

python -m pip install --upgrade pip

추가로 현재 Python과 pip 경로를 확인해 두면 문제 구분에 도움이 됩니다.

python --version
python -m pip --version
where.exe python
where.exe pip

7. uv를 함께 쓰는 경우

uv는 pip와 동작 방식이 조금 다를 수 있습니다. Windows 신뢰 저장소에 회사 인증서가 이미 들어가 있다면 --system-certs 옵션을 우선 시험하는 것이 좋습니다. 

uv --system-certs pip install requests
uv --system-certs pip install numpy
pip는 PIP_CERT 방식으로 해결되더라도, uv는 별도로 --system-certs가 필요할 수 있습니다.

8. 인증서 체인과 Intermediate CA 확인

루트 인증서만으로 충분하지 않은 경우도 있습니다. 회사 보안 장비가 Intermediate CA를 함께 사용하면 루트 하나만 지정했을 때 여전히 검증 실패가 날 수 있습니다.

  1. 브라우저에서 https://pypi.org에 접속합니다.
  2. 주소창의 사이트 정보에서 인증서를 열고 인증 경로를 확인합니다.
  3. 루트 CA 아래에 회사 Intermediate CA가 있는지 확인합니다.

예를 들면 이런 구조일 수 있습니다.

LG CNS Co. Ltd v3
  └─ 회사 Intermediate CA
      └─ pypi.org
이 경우에는 루트 인증서만이 아니라 Intermediate CA도 함께 준비해 체인을 맞춰야 할 수 있습니다.

9. --trusted-host는 임시 우회로만 사용

급한 상황에서는 pip 업데이트나 설치를 테스트하기 위해 --trusted-host를 붙일 수 있습니다. 다만 이는 인증서 검증을 우회하는 성격이 있으므로 상시 설정으로 두는 것은 권장하지 않습니다. 

python -m pip install --upgrade pip --trusted-host pypi.org --trusted-host files.pythonhosted.org
이 방식은 원인 진단용 또는 일시적 우회용으로만 사용하고, 장기적으로는 회사 루트 인증서와 체인을 정확히 등록하는 쪽이 안전합니다.

10. 권장 순서 요약

  1. LG CNS Co. Ltd v3 인증서를 Base-64 X.509 .cer로 내보냅니다.
  2. C:\certs\LG-CNS-Root-CA.cer에 저장합니다.
  3. 현재 세션에서 $env:PIP_CERT를 설정합니다.
  4. python -m pip install --upgrade pip로 테스트합니다.
  5. 성공하면 사용자 환경 변수 또는 pip config set global.cert로 영구 적용합니다.
  6. uv를 쓴다면 uv --system-certs도 확인합니다.
  7. 여전히 실패하면 브라우저에서 인증서 체인을 확인해 Intermediate CA 필요 여부를 봅니다.
$env:PIP_CERT = "C:\certs\LG-CNS-Root-CA.cer"
python -m pip install --upgrade pip
